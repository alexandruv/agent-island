# Snapshot boundary (schemaVersion 1)

`Snapshot` in `src/contract.ts` is the interface for the later read-only backend. The MVP imports fixtures; it makes no feed requests. Producers must normalize and validate data before supplying it. No shell commands, credentials, raw logs, permits or action endpoints belong in this public contract.

- `project.id`, `Agent.id`, `Issue.id`: stable, unique opaque identifiers, not array indexes. Issue number/title are display fields. IDs must be DOM-safe and unique across both lists.
- `capturedAt`: UTC ISO-8601 capture timestamp. `status.online` describes feed connectivity; `stale` describes freshness; `source` is `demo`, `live` or `cache`. Offline always displays cached data stale, even if a producer fails to set `stale`. This MVP's fixed capture time describes a fixture, not current host health.
- Agents carry a normalized station and state (`working`, `idle`, `waiting-permit`, `failed`, `stuck`, `needs-human`, `closed`, `unknown`). Missing context is `null`; nonfinite/out-of-range percentages display unknown. `latestLog` is one supplied **sanitized** line or `null`; upstream must remove secrets, personal paths and unrestricted output. UI inserts text, never log HTML, and generates no log claims.
- Issues carry normalized labels, explicit `authorizedPendingClaim`, and nullable `mergedAt`, `previewReadyAt`, `closedAt` timestamps. Queued/pending claim → 2; working → 3; review → 4; reworking/needs-human → 5; ready-for-human → 6. Unclassified intake → 1; closed → Archive. Explicit merged metadata → 6, or 7 only with preview metadata and a valid preview URL. Conflicting labels prioritize needs-human/rework, then ready-for-human, review, working, queue.
- `previewUrl`: nullable actual verified HTTPS URL, never inferred or fabricated. Credentials in URLs are rejected. Public link eligibility additionally requires live, online, fresh data and an issue with both explicit merge and serving-preview timestamps. Demo/cache cannot attest to preview availability. Later integration must verify provenance, not merely accept arbitrary strings as trusted metadata.

Fixture switching exercises online and offline states only. Production lock is independent of snapshots and has no unlock path. Any future feed renderer must reconcile entities by stable ID; this MVP's geometry is assembled for its fixed fixture, while lanes derive from the typed snapshot.

Issue #10 now supplies this boundary through optional read-only server routes without changing the fixture-driven visual UI. Transport adds allowlisted per-source status and a nullable host heartbeat; see [collector/feed](collector-feed.md). The collector deliberately omits raw display strings, logs, claims and unverified merge/preview metadata.
